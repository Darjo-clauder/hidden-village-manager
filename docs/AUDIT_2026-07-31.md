# Structure & Feature Audit — 2026-07-31

Full read of the codebase at HEAD `0ede7e5`, with two lenses: **depth/replayability**
and **what actually blocks a Steam release**. Written to be read cold.

Prior docs remain accurate on their own terms — `EXPANSION_ROUTES.md` (2026-07-02) is
essentially fully shipped, and `DEPTH_PASS_2026-07-19.md`'s four quick wins (S2/M3/D2/E1)
all landed. This audit covers what those two don't: the shape of the thing as a
*product*, and the gap between "systems exist" and "runs are worth repeating."

---

## 1. Shape of the codebase

~35,000 lines, excluding tests-as-content.

| area | files | lines | notes |
|---|---:|---:|---:|
| `client/js` (core) | 26 | 10,655 | tick, state, UI, renderers |
| `client/js/panels` | 30 | 10,305 | one module per screen |
| `shared/utils` | 50 | 3,967 | pure logic, the tested layer |
| `shared/constants` | 21 | 1,651 | content/data pools |
| `server` | 8 | 839 | optional multiplayer only |
| `tests` | 87 | 7,760 | 1,047 tests |

The architecture is sound and deliberate: **pure simulation logic lives in `shared/`
and is unit-tested; presentation and the tick live in `client/`.** Single-player runs
fully offline; the server is opt-in infrastructure for multiplayer only. Tauri packages
it as a desktop `.exe`. That's the right shape for a Steam single-player title.

### The one structural liability

`adv()` — the monthly tick — spans **lines 685 to 3610 of `client/js/adv.js`: a single
~2,900-line function.** Every system's per-month hook is inlined into it. It works, and
1,047 tests pass around it, but:

- it cannot be unit-tested (and isn't),
- the order of operations between systems is implicit and only discoverable by reading it end to end,
- every new system makes the next one harder to add safely.

This is the single highest-risk file in the project and it is the one with no test net.

### Test coverage, stated plainly

- `shared/utils`: **43 of 50 modules have dedicated test files.** Genuinely good.
  Untested: `bloodline`, `debt`, `debug`, `escapeHtml`, `formation`, `nanoid`, `scoutAggregation`.
- `client/`: **zero automated coverage.** No test file imports `adv.js`, `state.js`,
  `ui.js` or any panel. All 1,047 tests exercise pure `shared/` functions.

So ~21,000 lines — including the entire tick and all 30 screens — are verified only by
manual browser QA. For a paid release that is the main engineering risk.

## 2. Feature inventory

30 panels across 9 nav groups:

- **Village** — Overview, Finances, Upgrades, Warden Path, Legacy, Chronicles, Memorial
- **Roster** — Shinobi, Squads, Depth Chart
- **Missions** — Missions, Meetings, Clans, Safehouses
- **Development** — Youth Academy, Prospects, Scouting Network
- **Staff** — All Staff
- **Competitions** — Adept Exam, Five Warden Summit, Event Log
- **Diplomacy** — World, Intel, Trade Routes
- **Primals** — Beast Status
- **Market** — Transfer Market

### Systems that are genuinely deep

These have real decisions, delayed payoff, and compounding consequence:

- **Match engine** — seeded possession sim under a fixed-result governor, 3-tier tactics
  with identity auto-mapping, situational triggers, L/P/Z/S overlays, unified event log
  feeding ticker + stats sheet, multi-squad bracket boards. The most developed subsystem.
- **Economy** — salary cap with luxury tax, zero-sum budget allocation that ramps over
  ~2 quarters (a bet, not a readout), sponsor negotiation with mood, debt, prestige
  megaproject sinks, populace support.
- **Roster/development** — personality, traits, dreams, chakra elements, clans, career
  trajectory with peak ceilings, dev paths, mentorship, injuries → trauma → rehab plans.
- **Owner mandate** — 3 council mandates set each January, evaluated each December,
  confidence swings, and **two consecutive bad years dismisses you.** Real job security.
- **Recent depth pass** — depth-chart pressure, squad cadence, intel-as-ammunition
  leverage plays, budget ramp. All four wired and live.

### Systems that are shallow relative to their data

- **Diplomacy.** The data is rich (h2h history, grudges, personalities, memories, eras,
  minor-nation relations) but the player's verbs are still close to tribute/appease/gift.
  Leverage plays (D2) helped; formal alliances with obligations (D1) were never built.
- **Missions.** Approach picker and micro-calls are real, but chains have no memory —
  a chain is still three independent rolls rather than one unfolding operation (M1).
- **Succession.** Veterans retire and a slot empties. No mentor→successor transfer (S3).

## 3. Replayability — the honest gauge

### What varies between runs (good)

- **5 start scenarios** — Standard, Fledgling, Established Power, War-Torn Borders, Beast Keeper
- **World climate** rolled fresh per game — economy × threat, affecting income and raid rates
- **4–5 rival villages** drawn from a pool of 12, with randomised warden, personality,
  strength, relations and roster; strong rivals may pre-hold Primals
- **Procedural rosters** — elements, clans, personalities, dreams, archetypes; player
  village gets its own element affinity
- **World eras** that shift over a long run; shuffled warden-event queue

Content pools are substantial: ~98 mission templates, 12 great villages, 8 minor nations,
35 clans, 22 arenas, 7 mandates, 5 warden paths, 8 prestige projects.

### What carries between runs

**Nothing.** This is the headline finding.

`shared/utils/dynasty.js` documents a complete meta-loop: a 30-year dynasty clock, an
heir handoff at year 30, a computed dynasty grade, and `inheritedBonuses(grade)` for the
next run. The grade and progress are wired into the Legacy panel and display correctly.

But the handoff writes `G.dynastyHandoffRecord` and **nothing ever reads it.** There is
no persistent store outside the save file, and starting a new game wipes the save. So:

> A player who completes a 30-year dynasty — the game's stated long arc — receives a
> grade, is shown the bonuses they earned, and then starts their next run with exactly
> the same power as their first.

The most important replayability hook in the game is written, displayed, and disconnected.
Fixing it is mostly wiring, not design.

### The other replay pressure

A run is **360 monthly turns** at 30 years. That is very long for a management sim, and
the mandate/dismissal system is currently the only thing that can end a run early. Worth
deciding deliberately whether the intended experience is one 30-year dynasty or several
shorter arcs — that choice drives everything about how the meta-loop should pay out.

## 4. Steam release gaps

Hard gaps, verified against the code rather than assumed:

| gap | state | severity |
|---|---|---|
| **Audio** | **None at all.** No `Audio`, no `AudioContext`, no asset pipeline. Zero music, zero SFX. | Blocker |
| **Options/settings menu** | **Does not exist.** No volume, no resolution, no rebinding, no accessibility panel. | Blocker |
| **Achievements** | None. No Steam SDK integration. | Blocker (expected of the platform) |
| **Onboarding** | One dismissible dashboard card, Y1 M1–4. No tutorial. | High |
| **Meta-progression** | Written, not wired (see §3). | High |
| **Key art / capsules** | Emoji-only art. Fine in-game; store page needs real assets. | High (non-code) |
| **Client test net** | 21k lines, zero coverage. | High |
| **Localization** | Foundation only (P0/P1). ~28 panels of inline strings unextracted. | Medium |
| Code signing | Not done | Blocker (non-code) |
| Steam Direct ($100) | Not paid | Blocker (non-code) |

Audio is worth calling out specifically: it is the single largest perceived-quality delta
available. A silent management sim reads as unfinished to a store-page visitor regardless
of how deep the simulation is.

## 5. Suggested chart

Ordered by (impact on shippability) ÷ (cost), not by interest.

**Tier 1 — makes it feel like a product. No gameplay dependencies, can run in parallel.**

1. **Audio pass.** Ambient track per season/screen + UI SFX + match-event stings.
   Largest perceived-quality gain per hour of work in the whole list.
2. **Options/settings menu.** Volume buses, existing colorblind toggle, reduced motion,
   autosave cadence, text size (the type ramp already makes this a one-token change).
3. **Achievements.** ~30, mapped onto events the game *already* fires — chronicle
   milestones, mandate outcomes, dynasty grades, first S-rank. Data exists; this is wiring.

**Tier 2 — makes runs worth repeating.**

4. **Wire the dynasty meta-loop.** Persistent store outside the save; handoff applies
   `inheritedBonuses` to the next run; surface the lineage. Mostly connecting code that
   is already written and tested.
5. **Decide the intended run length**, then tune the 30-year clock to it.
6. **Guided first year** — replace the dismissible card with a real onboarding path.

**Tier 3 — depth flagship.** One multi-session arc, per `DEPTH_PASS` step 5:
D1 alliances with obligations, M1 mission chains with memory, or S3 succession.
D1 has the best ratio — the diplomatic data is already rich and currently read-only.

**Tier 4 — engineering, before the codebase gets harder.**

7. **Break up `adv()`** into per-system tick modules in the existing `client/js/tick/`
   pattern (`offSeason.js` already shows the shape).
8. **Client test net** — at minimum a headless harness that advances N turns against a
   seeded state and asserts invariants. This is what makes Tier 1–3 safe to build.
